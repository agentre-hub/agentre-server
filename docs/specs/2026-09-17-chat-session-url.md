# 会话详情并入 /chat 地址

> Status: Approved
> Owner: server 控制台前端 / 会话页
> Last updated: 2026-09-17

**Objective:** 一条会话只有 `/chat/:conversationId` 这一个可寻址入口：桌面端在 `/chat` 右栏打开、移动端全屏打开，独立的 `/devices/:did/sessions/:cid` 详情页不再存在。

**Hard invariant:** 新标签打开、刷新、复制链接、浏览器前进后退、移动端返回列表这些靠地址成立的能力不得丢失；relay attach、审批、发消息、转录补齐等详情行为只换宿主、不变实现；账号镜像以外的会话（未保存行）照旧可读可操作。

## Problem

1. **同一个动作两种落点。** 2026-09-17 线上报告：桌面端 `/chat` 的机器组里点两条对话，一条在右栏展开，另一条跳到 `/devices/1/sessions/<cid>` 独立页。根因在 `de42550` 之前的版本（已验证）：收起的组里露出的「需要你」行由共享 `SessionGroup` 渲染，宿主 `renderLink` 不拦默认导航，右栏打开后 `Link` 又导航走；普通行则拦了。`de42550` 统一链接渲染后该路径已修复，但只要独立详情路由还在，任何一个漏拦 `preventDefault` 的入口都会重新把用户带离 `/chat`。
2. **桌面端独立详情页与右栏重复。** `SessionDetailView` 同一份实现有 `form="page"` 与 `form="embedded"` 两种宿主（已验证：`SessionDetailView.tsx:270, 1827`）；页面形态只多出「设备 / 机器名」面包屑与「切换机器」按钮（`SessionDetailHeader.tsx:281-340`），左侧没有索引，读者离开了会话上下文。
3. **桌面右栏选中不在地址里。** 右栏开着哪条只存在 `Chat` 的组件状态（已验证：`Chat.tsx:195`，`/chat` 只读 `axis`、`machine`、`compose`）。于是新标签、刷新、分享只能借道独立页地址（行的 `href` 就是它，`SessionIndex.tsx:805`），导入完成也直接导航到独立页（`SessionIndex.tsx:673`）。
4. **地址里的设备号是冗余且会过期的寻址。** 会话身份是全局唯一的 `conversation_id`；已保存会话的当前承载设备由账号镜像行的 `device_fingerprint` 给出（已验证：`GET /v1/agent-sessions?conversation_id=`，`internal/api/agentsession/session.go:48-54`；前端 `fetchMirrorRow`，`sessionMirror.ts:87`）。把 `:deviceId` 钉在地址里，承载设备变化后旧链接指向错误机器。

## Actors and user stories

1. 作为桌面端用户，我希望点开任何一条会话都留在 `/chat` 右栏，同时地址反映当前打开的会话，这样刷新、新标签和后退都回到我看到的那一条。
2. 作为移动端用户，我希望从列表进入会话详情、按返回键回到原来的列表范围。
3. 作为分享或收藏链接的用户，我希望已保存会话的链接只含会话号，承载机器换了也仍然有效。
4. 作为查看机器上未保存会话的用户，我希望它同样能用链接重新打开，保存之后链接变成普通会话链接。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 会话地址为 `/chat/:conversationId` | 用户决定。会话身份就是 `conversation_id`，详情在 `/chat` 之内渲染。Rejected: 保留 `/devices/:did/sessions/:cid` 并在桌面端渲染 Chat——地址仍带冗余设备号，且设备页语义与会话页不符 |
| 2 | 旧地址 `/devices/:did/sessions/:cid` 不保留、不重定向，落到 404 | 用户决定（首发产品不留历史包袱）。Rejected: 重定向到新地址——保留一条需要长期维护的兼容路由 |
| 3 | 未保存会话地址为 `/chat/:conversationId?device=:deviceId` | 用户决定。未保存会话不在账号镜像里，只凭会话号无法得知机器；查询参数让它与已保存会话共用一条路径。Rejected: 不进地址——刷新即丢、移动端无法靠历史返回；打开即自动保存——未经「首次保存先告知」就把内容写进服务器，改变既有隐私约定 |
| 4 | 寻址顺序：账号镜像行的当前承载设备优先，其次 `?device=`，都没有则为「找不到」 | 镜像行是承载设备的真源，`?device=` 只是未保存会话的兜底。Rejected: `?device=` 优先——保存后又迁移的会话会连错机器 |
| 5 | 桌面端与移动端都以地址为选中会话的真源 | 用户决定（移动端也换新地址）。一份真源消除「右栏开着 A、地址说 B」的分叉；与 `Org` 页「选中态的真源是地址」同一做法（`Org.tsx:105`）。Rejected: 组件状态为主、再同步到地址——两份状态必然漂移 |
| 6 | 用户主动打开会话（点行、导入完成、新对话派发成功）push 历史记录 | 用户决定。后退回到上一条打开的会话，再退回 `/chat`。Rejected: 一律 replace——后退直接离开页面，移动端返回列表要另造机制；首条 push 其后 replace——连续浏览时后退无法回到上一条 |
| 7 | 系统性离开当前会话（打开中的会话被删除、进入「新对话」流程）与保存后去掉 `?device=` 使用 replace | 这些不是用户想回退到的位置：后退回一条已删除的会话或一个已失效的 `?device=` 形态没有意义 |
| 8 | 进入会话时保留当前 `/chat` 的查询参数（`axis`、`machine` 等） | 左栏的分组与收窄是用户选的范围，打开一条会话不应重置它。`device` 只属于会话寻址，不是索引范围 |
| 9 | 删除 `form="page"` 的桌面专属部分与独立详情路由页 | 独立页消失后面包屑、「切换机器」与路由页参数解析失去调用方。移动端详情的返回与机器状态头部保留 |
| 10 | `/devices/:did/sessions`（无会话号）保持重定向到 `/chat?axis=machine&machine=:did` | 它是设备页「查看这台机器的对话」入口，不是会话详情；不在本次删除范围 |

## Address contract

`/chat` 的路径段只有一个可选的 `conversationId`。不带它时页面是会话索引（桌面端右栏为空态或新对话流程，移动端为列表）；带它时页面打开这一条会话。

查询参数分两类：索引范围参数（`axis`、`machine` 等，既有语义不变）在打开、切换、关闭会话时原样保留；`device` 只在打开未保存会话时出现，关闭会话时随之移除。`compose=1` 保持既有一次性语义：被消费后移除，并且进入新对话流程时同时离开当前会话地址。

`conversationId` 不是合法 UUID 时直接呈现「找不到这条对话」，不向服务端发请求。

## Resolving the target machine

打开地址中的会话时按以下顺序确定连接哪台机器：

1. 调用方已持有这条会话的索引行（从左栏点开）时直接使用该行的设备，不额外请求。
2. 否则按会话号读取账号镜像行；命中时用它的 `device_fingerprint` 在账号设备名单里找到设备。
3. 镜像中没有这一行时使用 `?device=` 指定的设备号。
4. 两者都没有、或指定的设备不在当前账号设备名单中时，呈现「找不到这条对话」。

镜像行读取失败（网络或服务端错误）与「没有这一行」必须区分：失败时呈现可重试的加载错误，不得降级为「找不到」，也不得在失败时擅自使用 `?device=` 以外的猜测。镜像行存在但承载设备已被撤销时沿用详情视图现有的设备错误状态。机器离线时已保存会话仍可读取历史，行为与现状一致。

## Desktop

地址带会话号时右栏嵌入这条会话的详情；不带时右栏是空态或新对话流程。

- **点左栏一行**（含组内「查看全部」弹层里的行、键盘 Enter）：push 到该会话地址。已保存行地址不带 `device`，未保存行带 `device`。点开时手上已有的标题与索引行作为首帧种子交给详情，不因地址驱动而多等一次往返。修饰键或中键点击交给浏览器在新标签打开同一地址。
- **新对话派发成功**：push 到新会话地址，派发时已知的标题、首句、Agent、模型/力度未钉住提示、轮次开始时刻作为首帧种子；这些种子不进地址，刷新后按正常路径重新获取。
- **导入完成**（含「早就导过」）：push 到被导入会话的地址，停留在 `/chat` 右栏。
- **右栏开着的会话被删除**：replace 到不带会话号的 `/chat`（保留范围参数）。
- **进入新对话流程**（顶栏新建、项目/Agent 组头 ＋、`compose=1`）：replace 到不带会话号的 `/chat`。
- **保存当前带 `device` 的会话成功**：replace 去掉 `device`，右栏不重挂、不闪烁。
- **直接打开或刷新会话地址**：右栏打开该会话；左栏保持地址给出的范围，不自动切换轴或滚动定位，该会话在当前范围内可见时高亮，不可见时无高亮。
- **后退 / 前进**：右栏跟随地址切换；后退到不带会话号的 `/chat` 时右栏回到空态。

## Mobile

地址带会话号时整屏显示会话详情，不带时显示列表。点行、导入完成、新对话派发成功与桌面端同样 push 到会话地址；删除、进入新对话流程、保存去掉 `device` 的地址处理与桌面端一致。

详情顶部保留返回按钮、机器名与在线状态。返回按钮回到不带会话号的 `/chat` 并保留进入时的范围参数；系统返回键走浏览器历史，从列表进入时结果相同。从外部链接直接打开时，返回按钮仍回到 `/chat`。

## Removed surface

- 路由 `/devices/:deviceId/sessions/:conversationId` 及其懒加载页面与预热。
- 详情视图路由页形态中仅桌面端存在的面包屑（设备 / 机器名）与「切换机器」按钮。
- 路由页从导航 state 解析首帧种子的逻辑；种子改由 `/chat` 在同一页面内传递。
- 文档中把详情描述为 `/devices/:id/sessions/:id` 路由的表述（`docs/design.md`）以及代码注释里对旧地址的引用，随实现同步改为新地址。

## Out of scope

- 后端接口与数据库：寻址所需的镜像行按会话号查询与设备名单均已存在。
- 桌面 Wails 应用与共享包 `@agentre-hub/agentre-ui`：`SessionRow` 的链接端口已由宿主提供地址，无需变更。
- `/devices/:did/sessions` 重定向与设备页本身。
- 左栏在直接打开地址时自动定位、切换轴或滚动到该会话。
- 为旧地址提供任何兼容跳转。
