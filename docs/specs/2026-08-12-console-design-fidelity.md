# 控制台设计稿忠实返工

> 状态：已批准
> 负责人：AgentRe Server 前端
> 最后更新：2026-08-12

**目标：** 让已登录控制台的外壳、总览、设备、对话、会话详情与审计页面在桌面和移动端忠实呈现 Pencil 正式产品界面，同时彻底排除设计旁白、评审标注和没有真实后端能力的伪交互。

**硬性不变量：** Pencil 只决定视觉与交互表达，不能凌驾于真实产品能力；界面不得展示虚构数字、虚构状态、无效按钮、无效开关或设计人员旁白，且不得回退现有认证、设备管理、会话关注、审批和中继能力。

## 问题

1. **现有实现只做了结构近似，没有忠实还原正式画板。** 运行时证据 `e2e/scratch/2026-08-11-console-design-alignment/screenshots/` 显示，总览、设备和对话页的层级、密度、行形态、移动布局与 Pencil 的 `IhldU`、`Q6qgs4`、`Ukz7i`、`HUELX`、`X9Mjl`、`uqEha`、`kpP7A` 和移动对话画板存在明显差异；上一轮验证主要证明元素存在，没有证明视觉一致。
2. **设计说明被误判为产品 UI。** 设备页右侧“撤销这台设备”长说明卡、审计页“这里记什么”、N1/N2 规则文字、“本轮改动只读”等内容服务于设计评审或能力解释，不是用户完成任务所需的常驻界面；将其实现为产品卡片会制造错误的信息层级。
3. **桌面和移动端沿用了同一结构的缩放版。** Pencil 为设备和对话分别给出独立移动形态，包括移动设备行、状态分组、底部导航和列表到详情的流程；当前移动端仍明显继承桌面壳与桌面卡片结构。
4. **共享形态没有形成统一组件契约。** 导航项、状态标记、统计项、设备行、会话行、筛选项和空态在页面内各自组合，导致尺寸、字阶、间距和状态表达跨页面漂移，也使逐页面并行返工容易重复实现。
5. **无后端数据的设计示例与真实产品边界没有被系统区分。** Pencil 中的用量、异常、审计、凭证、设备负载、接单开关、文件改动和自动挂起倒计时包含示例数据或未来能力；当前后端并不提供其中多项数据，若照抄会形成虚假产品承诺。

## 角色与用户故事

1. 作为已登录用户，我希望控制台的桌面和移动界面与正式设计稿一致，以便在不同页面间获得稳定、清晰的视觉层级和操作预期。
2. 作为设备管理员，我希望撤销设备等危险操作只在真实操作入口和确认步骤中出现，而不是被长篇说明卡长期占据页面。
3. 作为对话用户，我希望桌面端能在列表旁查看真实会话详情，移动端能自然地从列表进入详情，同时不会看到没有后端支持的虚假能力。
4. 作为维护者，我希望重复形态由共享组件承担，并由 `docs/design.md` 记录可复查的画板到代码契约，避免下一次页面各自漂移。

## 设计决策

| # | 决策 | 依据与否决方案 |
|---|---|---|
| 1 | 正式产品界面以指定 Pencil 画板为视觉真源，但只采纳用户任务流中的界面元素。 | 用户要求逐页对齐，并明确指出“撤销这台设备”等画板内卡片也是旁白。否决：按节点类型或是否位于正式画板内机械实现——说明卡可能被画成完整 UI，但仍不是产品功能。 |
| 2 | 使用“任务必要性 + 真实能力”双重判定旁白：不帮助用户完成当前任务，或只向设计/开发解释规则的内容，一律排除。 | 可覆盖 Note、Context、Prompt、Callout，也能覆盖伪装成卡片的说明区。否决：只过滤 Pencil 的 Note 类型——会漏掉画在 Frame 内的旁白卡。 |
| 3 | 无真实数据或端点时保留设计的信息层级与诚实空态，但不渲染可点击的假控件。 | 遵守仓库“不伪造后端”原则。否决：照抄示例数字、禁用但看似可用的按钮、点击后本地假成功。 |
| 4 | 设备撤销能力进入设备行的更多操作菜单，并继续使用确认对话框说明必要后果；页面不常驻“撤销这台设备”说明卡。 | 撤销端点真实存在，危险操作需要可发现但不应主导整页。否决：删除撤销能力；也否决保留右侧长说明卡。 |
| 5 | 桌面和移动采用各自画板的结构，而不是响应式缩放同一棵页面结构。 | Pencil 已分别给出设备、对话和导航的移动方案。否决：只调整断点、宽度和字号——无法得到移动端的信息顺序和交互流程。 |
| 6 | 桌面对话采用列表与真实详情同屏；移动对话继续采用列表进入详情。 | 与 `X9Mjl`/`uqEha` 和移动画板的任务流一致，并复用现有真实会话详情能力。否决：桌面右栏继续保持静态占位；也否决移动端强塞双栏。 |
| 7 | 移动底部导航只呈现真实可达的产品目的地；不存在“我”页面时不伪造入口。账号、语言和主题控制放入真实可达的现有控制面。 | 兼顾移动画板方向和真实路由边界。否决：增加指向占位页或无动作的“我”按钮。 |
| 8 | 审计页实现正式页面层级和诚实空态，不实现虚构日志、凭证、CSV 导出或撤销指定凭证。 | 审计后端当前不存在。否决：保留 ComingSoon；也否决用设计示例填表。 |
| 9 | 共享组件先冻结，页面再按所有权并发实现，最终由设计文档统一收口。 | 用户要求组件复用、逐页面并发和更新 `docs/design.md`。否决：每个页面独立复制样式——会继续产生漂移和文件冲突。 |

## 视觉真源与旁白判定

本轮只把以下节点的正式产品界面作为约束：外壳 `R969Y`、导航项 `ZC7pI`、移动底栏 `A6Z3k`；总览 `IhldU`；设备 `Q6qgs4`、`Ukz7i`、`HUELX`；桌面对话 `X9Mjl`、`uqEha`、`kpP7A`；移动对话 `IC5sH`、`C87ty`、`j571mC`、`eh9zO`；审计 `bKvB4`。`p5Orc` 只提供“优化后”会话列表的决策依据，不作为额外产品页面。

一个画板元素只有同时满足以下条件才进入产品：

1. 它服务于用户在该页面上的真实任务，而不是向设计、开发或评审者解释设计；
2. 它展示的数据能够从真实前端状态或后端接口获得，或者能够以明确的诚实空态表达缺失；
3. 它提供的操作存在真实结果和失败处理；
4. 它在对应桌面或移动画板中属于产品信息层级，而非标号、连线、比较说明、规则注释或示例讲解。

明确排除：所有 Note、Context、Prompt、Callout 编号/连线、“现状 vs 优化”的解释文字、N1/N2 等规则文字、“执行目标按顺序取第一个可用的”、“这里记什么”、“改动在设备上，这里不落文件”、设备页常驻“撤销这台设备”说明卡，以及其他即使被画成卡片、但只解释能力或操作后果的区域。

确认对话框中的简短危险后果说明不属于旁白，因为它直接支持用户作出不可逆操作决定；它只在用户主动选择危险操作后出现。

## 外壳与跨页面组件

桌面外壳按照 SideNav 与 TopBar 的正式比例、密度和状态层级呈现。品牌区、导航项、账号区、计数、新鲜状态和页面操作必须遵循统一组件形态；来源未知时不补默认数字或状态。搜索若没有真实搜索能力，应以明确不可用的语义呈现，不进入键盘顺序，也不能暗示快捷键已经生效。

移动端不复用桌面侧栏抽屉作为主导航，而采用画板的底部导航方向。底栏只包含真实可达目的地；页面顶部保留当前页面标题和真实操作。账号、语言、主题等现有功能必须仍可到达，且不能与底栏或页面操作争夺同一视觉位置。

导航项、状态标记、统计项、设备行、会话行、筛选项、危险菜单项和通用空态应形成单一共享实现。页面可以组合这些组件，但不得复制其尺寸、状态颜色、字阶或交互语义。

## 总览

当用户进入总览时，页面按照 `IhldU` 的统计区、待处理区、Agent 主区和辅助信息区建立层级。设备在线、待处理会话和 Agent 执行目标使用真实数据。无法由当前服务提供的今日用量、异常、本月用量、最近授权、安全与凭证数据保留设计所需的信息位置，但只显示统一的无数据表达；不得使用设计示例数字、IP、时间或事件。

待处理区域只有在真实待处理会话可判定时出现，并且只提供真实可执行的允许、拒绝、回复或查看动作。无待处理内容时，页面不为了匹配截图而制造示例卡，也不显示带零条假内容的紧急操作条。

桌面和移动分别按照可用宽度重新排序信息；移动端的统计、待处理和 Agent 内容不能仅缩小桌面列宽，也不能产生横向滚动。

## 设备

桌面设备页按 `Q6qgs4` 和 `Ukz7i` 的设备列表密度、图标、状态、元信息和展开层级呈现，浅色和深色使用同一语义 token。页面不渲染右侧常驻撤销说明卡。

每个可撤销设备通过行级更多操作进入“撤销设备”，随后出现确认对话框。确认后调用现有真实撤销能力；失败时保留对话上下文并显示真实错误，成功后刷新真实设备状态。不可撤销或没有对应端点的设备不显示该动作。

项目、可运行 Agent、会话数、在线状态等只在真实数据存在时显示。设备路径遵循隐私边界：只表达是否配置，不把路径内容搬到服务端控制台。接单开关、并发负载条等当前无真实能力的控件不渲染，也不以禁用开关冒充未来功能。

移动设备页按照 `HUELX` 的行式信息顺序、触控密度和底部导航重新组合，但同样省略无真实能力的负载与接单控件。所有危险操作在移动端仍通过行级菜单和确认步骤到达。

## 对话与会话列表

桌面对话页按正式画板形成固定列表区与可伸缩详情区。未选中或没有真实会话时，详情区按照 `kpP7A` 的空态层级呈现；存在选中会话时，右侧直接展示该真实会话的状态、转录、审批和输入能力，不再保留与数据脱节的静态占位。

会话列表采用 `p5Orc` 的优化结果：清晰的 Agent/状态层级、两行会话信息、真实筛选状态、选中状态、键盘导航和仅包含真实动作的菜单。设计对比中的编号、解释和推荐理由不进入产品。相同会话在“最近”和 Agent 分组同时出现时，键盘目标和选中高亮仍必须唯一。

详情区只呈现现有协议真实支持的内容。转录、审批、回复、停止、关注等真实能力继续可用；文件改动面板、自动挂起倒计时、权限模式、会话轮次、快速提示词等没有数据或协议支持的元素不渲染。设计中可复用但协议能够支持的视觉形态，应由现有真实数据驱动，而不是用固定演示文本填充。

移动端按照正式移动画板保留列表到详情的流程、状态分组、可触达的搜索/筛选、新建入口和底部导航。移动详情不强制复刻桌面双栏，不得出现横向滚动；没有会话时按移动空态画板呈现。

## 审计

访问审计页面时，用户看到与 `bKvB4` 一致的信息层级，而不是 ComingSoon。由于当前没有审计存储和查询接口，事件表、凭证区和告警区呈现明确的诚实空态，并且不显示示例事件、示例 IP、示例令牌数量或虚构告警。

CSV 导出、撤销单个凭证、忽略告警等操作在没有真实后端能力时不显示。画板中的“这里记什么”说明卡及其范围解释不进入产品。页面仍应在桌面、移动、浅色、深色下保持与其他控制台页面一致的外壳、标题、间距和无障碍层级。

## 主题、国际化与可访问性

所有颜色继续通过语义 token 表达，且浅色、深色都与对应画板关系一致。所有产品文案进入双语 i18n；旁白既不进入组件，也不为其创建 locale 键。重复形态的尺寸、字阶、状态颜色和圆角由共享组件与 `docs/design.md` 共同约束。

键盘用户能够到达所有真实操作：导航、筛选、会话选择、行级菜单、确认对话框和详情操作。菜单打开后管理焦点，Escape 可关闭；移动触控目标满足现有项目的最小尺寸约束。颜色不是状态的唯一表达，诚实空态能够被辅助技术识别，装饰图标不会制造重复朗读。

## 文档契约

完成实现后，`docs/design.md` 必须从实际代码和正式画板重新记录控制台外壳、共享组件、总览、设备、对话、审计、主题和响应式契约。它不得继续描述已删除的右侧撤销说明卡、伪搜索能力、虚构统计或其他上一轮错误实现，也不得抄录设计旁白。

文档需明确“正式 UI 与设计旁白的判定规则”，并为每个共享组件标明其视觉角色和适用页面，使后续页面只能复用而不是重新测量和复制。

## 范围外

- 新增审计日志存储、审计查询接口或 CSV 导出。
- 新增用量、异常、活跃凭证或登录历史统计后端。
- 新增设备接单开关、并发负载协议或服务端设备路径展示。
- 新增文件改动上报、自动挂起倒计时、权限模式或会话轮次协议。
- 为匹配 Pencil 示例而创建静态演示数据、假按钮、假开关或本地假成功。
- 新建没有真实目的地的移动“我”页面。
- 修改 Pencil 设计文件。

自动化无法可靠判断逐像素观感，因此最终运行时验证必须使用真实浏览器截图与对应 Pencil 节点并排比较。无后端数据的区块只能验证诚实空态；不得为了让截图接近设计示例而注入生产中不存在的能力。代码审查轴另外核验旁白没有进入组件或 locale、共享组件没有被页面重复实现、所有可见操作都有真实结果。
