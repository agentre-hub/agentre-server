# 控制台按失败的真实种类出页

> Status: Draft
> Owner: agentre-server（控制台）
> Last updated: 2026-09-09

**Objective:** 控制台在转发失败时说的话与实际发生的事一致，且用控制台自己的措辞；被转发应用自己的响应一个字节都不被改动。

## 上游规格

可观察的转发行为仍由 `agentre` 的 `docs/specs/2026-09-06-device-port-forward.md` 定义。本轮依赖的新扩展点由 `agentre` 的 `docs/specs/2026-09-09-forward-failure-attribution.md` 定义——**那一份先落地并推送，本仓才 pin。**

## Hard invariant

- 上游 `agentre` 仓在本轮的本仓部分**一行不改**。
- 不新增表、不新增迁移。
- 共享包已有的实现不在本仓重复一份。
- `/fw/` 不声明响应结构体，R19 守卫面不碰。

## Problem（都有运行期证据，见 `e2e/scratch/2026-09-09-console-port-forward-host/report.md`）

1. **被转发应用自己答的 502 被换成失败页。** 目标直连返回 `502 + upstream says 502`，经转发得到的是「端口上没有服务」那张页——服务在跑，页面却叫用户去起它（截图 `07-upstream-502-rewritten.png`）。
   根因：`internal/controller/portforward_ctr/rewrite.go` 的判据是**纯状态码**（当时规格决策 13 要求的），而在 writer 那一层，共享包的失败与转发回来的上游响应没有可靠的区分信号。
2. **不改写的 403 / 404 文案是桌面端口径。** 在控制台里把映射停用后打开它，得到共享包原文「到 **agentre** 里把它启用之后再打开」——用户刚刚就是在控制台里停用的，而且未必装了桌面端。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | pin 到上游那一轮推送的修订，`go.mod` 与 `frontend/package.json` 的 `agentre-wire` **同时**移（`agentre-ui` 随之），并重生成 `pnpm-lock.yaml` | `internal/pkg/wireversion/wireversion_test.go:87` 的 `TestPins_` 要求两条 pin 来自同一 commit |
| 2 | **`wireversion.MinSupported` 与 `Protocol` 都不动，仍是 `0.5.0`** | 上游本轮不碰 `.proto` 与生成物，协议不换代。`TestProtocol_` 比的是 pnpm-lock 里的包版本与 `Protocol`，两者仍相等。**这一轮不会再把任何 agentred 挡在门外** |
| 3 | 装上游的渲染钩子，**删掉** `rewrite.go` 那层按状态码嗅探的 writer | 钩子只在代理自己的失败上被调用，改写层存在的唯一理由（分不清是谁答的）消失了。留着它就是留一条会误伤上游响应的路 |
| 4 | **删掉决策 13 那次二次在线读**（`badGateway` 里的 `IsDaemonOnline`） | 种类直接分开「设备够不着」与「端口上没有服务」，不需要再猜。顺带省掉每次 502 都多一次 Redis 往返 |
| 5 | 控制台为**能碰到的四种**各出一张完整 HTML 页：映射已不在 / 映射已停用 / 端口上没有服务 / 设备够不着 | 用户决定。Problem 2 只有让控制台自己出这四种的文案才算真修好 |
| 6 | 其余三种（上游断开 / 转发未完成 / 升级失败）给简短纯文本，用控制台自己的措辞 | 它们要么是瞬时的、要么用户无从下手，一整张页给不出比一句话更多的东西。Rejected: 七种全出页 —— 三张没人能照着做任何事的页 |
| 7 | 控制台自己产生的失败（地址形状不对、设备查不到 / 不是你的 / 已撤销、池未装配）**维持今天的答复不变** | 它们不经过共享代理，本轮的钩子够不着它们；而它们今天的口径（三态逐字节相同的 404、503）是上一轮定过且运行期验证过的 |
| 8 | 四张页沿用今天 `failpage.go` 的形态与那条 i18n 豁免 | 豁免的理由未变（用户在转发地址上、不在 SPA 路由里）。射程从两张扩到四张，豁免注释要跟着改 |

## 可观察的要求

1. **前提**：设备在线、映射存在且启用，被转发应用自己答一个 5xx。**动作**：打开该地址。**结果**：拿到应用自己那个响应，状态码与正文**逐字节原样**，控制台不插手。
2. **前提**：映射已被删除。**动作**：打开该地址。**结果**：一张完整页，说明这个端口的映射已经不在了，用控制台的措辞，带「刷新」与「回到设备」。
3. **前提**：映射存在但已停用。**动作**：打开该地址。**结果**：一张完整页，说明它被停用了、**并指向控制台**（不是桌面端），带两个出口。
4. **前提**：设备在线、映射启用，但该端口上没有服务在监听。**动作**：打开该地址。**结果**：「端口上没有服务」页，说明要去那台机器上把服务起起来。
5. **前提**：设备离线。**动作**：打开该地址。**结果**：「设备离线」页，说明要等它回来。
6. **前提**：以上任意一种。**动作**：观察服务端。**结果**：不再为区分失败种类而额外读一次在线状态。
7. **前提**：任意情形。**动作**：打开一条形状不对的 `/fw/` 地址、或未登录访问。**结果**：与本轮之前完全相同（401；三态逐字节相同的 404；不回落 SPA 外壳）。

## Non-goals

- 不改被转发应用自己的任何响应。
- 不动上游共享包（那是上一份规格的事）。
- 不碰桌面端。
- 不改 `/fw/` 的地址形状、鉴权与前缀剥离。
- 不给这四张页做 i18n（决策 8 的豁免继续，文案限定中文）。

## Testing decisions

| Seam | What it verifies |
| --- | --- |
| 控制器的种类→页映射 | 四种各自出对应的页；三种出简短纯文本；状态码不变 |
| 透传用例 | 被转发应用自己的 5xx / 4xx 逐字节原样（**这条是 Problem 1 的回归守卫**） |
| 不再二次在线读 | 502 路径上在线判定被调用的次数从 2 降到 1 |
| 既有看门用例 | 101 升级、流式、`Unwrap`/`Flusher`/`Hijacker` 仍绿；鉴权与形状那七条仍绿 |
| pin 守卫 | `TestPins_` / `TestProtocol_` 在移 pin 之后仍绿 |

## 已知约束

- 决策 6 那三种仍是裸文本；用户看到的是一句话而不是一张页。
- 与上一轮相同：不得给共享代理传非默认 `WindowBytes`。

## Out of scope

- 路径前缀式转发让**根相对 URL** 的应用断掉（运行期发现 3）。那是这个地址形态的固有后果，要改得换形态（子域名），不在本轮。
