# 控制台接上文件预览：宿主这一半

> Status: Approved
> Owner: 控制台前端
> Last updated: 2026-09-08

**Objective:** 让浏览器控制台的用户点转录里的文件路径就能在详情列右侧看到那个文件此刻在那台机器上的样子——代码 / Markdown / 图片 / 与 HEAD 的对比——以及四种失败各自如实说清楚。

**上游规格：** 观察到的行为由 `agentre` 仓已批准的 [`docs/specs/2026-09-06-console-file-preview.md`](https://github.com/agentre-hub/agentre/blob/dev/docs/specs/2026-09-06-console-file-preview.md) 定义（分栏 420 + 476、七个状态、只有离线给重试、入口判定两道口径）。**那份规格是可见行为的权威，本规格只定这一侧怎么接**：钉哪个版本、cwd 从哪来、失败怎么归类、Monaco 怎么装、标签状态住在哪。冲突时以上游规格为准。

**Hard invariant:**

- **服务端 Go 一行不改。** 文件正文与路径只经中继在浏览器与那台机器之间流过，不进服务端任何响应结构体、不落库、不记正文——R19 的守卫面不变。
- **`agentre` 仓一行不改。** 本轮是跨仓交付的第 2 步：共享实现已经在 `agentre` 里落地并推送，这一侧只挪 pin 并接线。需要改共享包才做得成的事，是另一轮。
- **不在本仓复制共享包已有的东西。** 预览面板、标签条、四类视图、`previewKind` 判定、失败态文案都从 `@agentre-hub/agentre-ui` 消费，本仓不留第二份。
- **宿主没接端口时入口整个不渲染**，而不是渲染出来点了没反应（共享包既有的能力探测约定）。

## Problem

1. **控制台里的文件路径至今是死文本。** `src/lib/transcriptPorts.ts:70-73` 明确不提供 `openPath` 与 `readWorkspaceFile`，注释写明理由是「桌面能力，浏览器里不存在」；按能力探测约定，转录里所有与文件相关的入口因此整个不渲染。`src/components/session/Transcript.tsx` 也从不给转录传 `cwd`，链接连「在不在 cwd 内」都判不出来。

2. **能力早就在线上，缺的只有这一侧。** `workspacefs.*` 七个方法登记在 `@agentre-hub/agentre-wire` 的方法表里，agentred 用 `requireAuth` 守着；浏览器已经在用完全相同的裸传路子跑 `remotefs.*`（`src/lib/remotefs.ts`，该文件注释写明「服务端一行代码都不需要改」）。

3. **上游刚把最后一块补齐。** 2026-09-08 的 `agentre` 协议轮给 `workspacefs.readFile` 加了稳定错误码 `-32043`（文件不存在）。在那之前，控制台无论怎么接线都到不了「文件不存在」这一态——它的每一条会话都是远端会话。

## Actors and user stories

1. 作为在浏览器里盯远端会话的用户，我希望点转录里的文件路径就能看到它现在的内容，这样我不必切到那台机器前面。
2. 作为审查 agent 改动的用户，我希望在浏览器里也能看到 diff，这样我能判断这一轮改得对不对。
3. 作为维护者，我希望这一侧只有接线没有实现，这样两端不会各自长出一套预览。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | pin 钉到 `agentre` 的 `dev@472d9e0a`（或其后已推送的提交） | 那是共享包带上 `file-preview/*` 与 `previewFile` 端口、且协议轮的 `-32043` 已经在 daemon 侧产出的第一个已推送版本。Rejected: 钉当前的 `18b6b9c8` —— 它没有 `-32043`，「文件不存在」这一态到不了 |
| 2 | cwd 取自**中继上的实况会话摘要**（`sessionList` 应答里的 `cwd`），不经服务端 | R19 只禁止路径进服务端的响应面；中继是浏览器与那台机器之间的字节透传，摘要是那台机器直接给浏览器的。这是本仓拿得到 cwd 的唯一合规来源。Rejected: 让服务端下发项目路径 —— 正是 R19 要挡的东西 |
| 3 | 那台机器离线时**不出入口**（链接维持死文本） | 离线 ⇒ 取不到实况摘要 ⇒ 没有 cwd ⇒ 落进上游规格既有的那条「会话根本没有 cwd 的，不出入口」。零新增状态。用户决定。Rejected: 缓存上次已知 cwd 仍出入口 —— 解释得更好，但要新增一份会过期的宿主状态（那台机器上改了项目路径就不准了） |
| 4 | 失败归类**认错误码，不认文案** | 与 `src/lib/remotefs.ts:118-145` 同一条理由：message 是那台机器上的 Go 错误文本，改一个字就把判断打散，而错误码是写进 wire 契约的稳定值。映射：`-32043` → `notFound`；RelayClient 自造的 `-1`（连接未就绪 / 已关闭 / 断线）→ `offline`；其余不归类，如实显示它自己的文案 + 重试 |
| 5 | `content` 这一格按**类型分两条路**还原 | wire 上它是 `bytes`。文本要 UTF-8 解码成正文，图片要 base64——共享包的 `ReadFileResult` 正是这么约定的（`contentType` 非空即图片）。本仓已有先例：`relayClient.ts` 的 `acceptedBinaryFields` 就是为「这确实是二进制」准备的（提交 6ae6862）。Rejected: 一律 base64 后在组件里再判 —— 会把「渲染什么」的判定搬回宿主 |
| 6 | Monaco 由宿主**懒加载**并经 `monaco` prop 注入 | 共享包对 monaco 只有类型依赖，装载器与 worker 环境必须留在宿主（worker 靠 Vite 的 `?worker` 打成独立 chunk，而包是纯 tsc 构建）。只在用户真的点开一个文件时才装。上游规格决策 5 |
| 7 | 标签集合与「当前是哪个」的状态住在**宿主**，不进共享包 | 共享面板收的是 `tabs` / `activePath` / `sourceKey`，两端各自的布局与临时/常驻语义由各自的 store 回答。上游规格决策 3 |
| 8 | 预览栏 **420 定宽、不可拖**；关掉最后一个标签整栏收起 | 上游规格决策 8 已按 `/chat` 的真实宽度定死（详情列 896 = 转录 476 + 预览 420），零新增能力，会话列表列与 `ResizableSidebar` 都不动 |

## 取数与失败：宿主适配层

**前提**：预览面要读一个文件。**动作**：宿主的取数端口发出一次中继调用。**结果**：拿到正文与视图标志，或者拿到一个**带归类标记**的失败。

两个端口各对一个已登记的方法：`readFile` → `workspaceFsReadFile`，`gitFileContent` → `workspaceFsGitFileContent`，请求都带 `{root, relPath}`，`root` 是上面那条实况 cwd。

失败一律 reject，由预览面落到自己的错误态；宿主只负责在 reject 值上贴 `kind`（`offline` / `notFound`），贴不出来的不贴——共享包对不带 `kind` 的失败按「未归类」处理，如实显示它自己的文案加重试。宿主**不吞异常、不做 toast**，这是共享包端口契约已经定下的。

`tooLarge` / `binary` 是成功应答上的视图标志，不是失败，原样交给面板。

## 入口：转录里的文件链接

**前提**：用户看着一条会话的转录，某个块里带有指向会话工作区内文件的路径。**动作**：点它。**结果**：详情列右侧的预览栏开出这个文件的标签并显示内容。

出不出这个入口沿用上游两道判定，本仓不新增口径：路径要解析成 cwd 之内的相对路径，扩展名要在预览 allowlist 内。**控制台里不在 allowlist 的不出入口**——它没有「交给外部应用」这条退路。

要让这两道判定跑起来，宿主必须把实况 cwd 传进转录（今天没传）。cwd 为空（那台机器离线、或摘要还没到）时两道判定都不成立，链接维持今天的死文本。

## 预览开在哪

详情列横向分成两栏：左侧转录 476，右侧预览 420，两栏同时可见。预览栏由标签条、路径条、内容区三段构成；临时标签以斜体标名。关掉最后一个标签时预览栏整个收起，转录回到全宽。

完整的视觉与状态集见上游规格与其设计源（`agentre.pen` 的 `B1` 与 `B2 状态集`）。

## Out of scope

- 控制台里的「目录 / 变动 / Git」文件侧栏——上游规格已列为非目标。
- 在浏览器里编辑或保存文件。
- 目录浏览（`remotefs.*` 已经在做的另一件事）。
- 桌面端的任何改动。
- 端口转发（`agentre` 仓的 `2026-09-06-device-port-forward.md`，另一轮）。

## Testing decisions

| Seam | What it verifies | Prior art |
| --- | --- | --- |
| 取数适配层（RelayClient 打桩） | 两个端口各发出对应方法且带上实况 cwd；`-32043` 贴成 `notFound`、`-1` 贴成 `offline`、其余不贴标记；文本与图片两条还原路各自正确 | `src/lib/remotefs.ts` 的既有用例 |
| 转录入口 | 有 cwd 且扩展名在 allowlist 时点链接开出预览标签；cwd 为空时链接不出入口；宿主不提供 `previewFile` 时入口整个不渲染 | `src/components/session/__tests__/` 既有转录用例 |
| 会话详情布局 | 开预览时分成两栏且转录仍可见；关掉最后一个标签后预览栏收起、转录回到全宽 | `src/__tests__/chat.test.tsx` |
| 失败态动作 | 「不存在」无动作按钮、「离线」有重试——**打在宿主装配根上**，让打桩的中继返回真实错误码，不得用注入预先贴好 `kind` 的 error 来满足 | `agentre` 修正轮同名的那条口径（那次偷懒正是缺陷漏出去的原因） |

不自动化的一条：**Monaco 在构建产物里确实是懒加载的**。由收尾时看一次 `pnpm build` 的分包确认，并在报告里如实记下看到的 chunk。
